# 模型服务、Agent 配置与多模态对话前端收口

日期：2026-08-05

版本：v0.1.2

范围：semantic-web

## 为什么

模型服务、API 密钥和端点原先分散配置，用户难以判断哪个配置真正生效；Agent 页面也无法可靠
区分配置模型与本轮实际模型。图片上传使用服务端 URL 前缺少稳定本地预览，运行历史中的模型、
工具和推理信息恢复不完整。本次变更围绕已有 IDE 对话工作台收口这些基础调试能力。

## 主要内容

### 模型服务与端点管理

- 增加 MiniMax 与 Anthropic Claude 服务商预设；MiniMax 提供国内、国际区域配置及 M3 多模态模型。
- 连接模型服务时直接录入 provider 密钥，并显示密钥来自环境变量、设置存储或未配置。
- 连接服务后按预设生成可选端点，不再要求用户单独建立密钥与端点绑定。
- 已配置密钥的服务商使用明确状态样式；设置页显示当前服务端实际配置文件位置。
- 支持删除无效端点；删除默认端点时原子切换到可用端点或 mock，删除服务最后一个端点时同步清理密钥。

### Agent 模型配置与运行校验

- Agent 页面可从当前已接入端点选择主模型、深度模型、推理 effort 和 reasoning 可见性。
- 编辑草稿期间暂停轮询覆盖，避免用户尚未保存的选择被后台刷新冲掉。
- 保存后重新读取服务端 Agent 配置，只有服务端确认一致才提示生效。
- 对话运行检查器分别展示 Agent 配置模型、本轮实际端点/model ID 和回退状态，避免把配置值误当成实际运行值。

### 图片与对话状态

- 修复粘贴、拖入或选择图片后 Blob URL 被提前释放导致初始预览失败的问题。
- 本地预览、上传后 Artifact 引用和历史鉴权 URL 分别管理，支持一次添加多图及逐张删除。
- chat store 保存服务端返回的实际模型解析信息，切换会话或 REST 恢复后仍可查看。
- 运行检查器继续展示推理策略、工具活动、Agent 归属与 Artifact。

## 接口与影响面

- 消费设置接口返回的 `config_path`、`key_sources` 和 provider 级密钥状态。
- 消费 `message.done.payload.model` 与历史 run metadata 中的实际模型解析信息。
- 删除端点使用设置更新接口一次提交端点集合与新的默认模型，避免中间态引用已删除端点。
- 无新增前端运行依赖。

## 验证

- `npm test -- --run`：19 个测试文件、179 个用例通过。
- `npm run lint`：ESLint 与 Prettier 检查通过。
- `npm run build`：Vite production 构建通过；仅保留既有 Sass deprecation 与 chunk 体积提示。
- 单测覆盖 provider 连接/删除、默认模型切换、Agent 保存一致性、实际模型恢复及图片预览生命周期。

## 已知限制与后续

- 真实 MiniMax、DeepSeek、Claude 的密钥和区域仍需分别做人工连接验收，密钥不会进入自动化测试。
- 独立 Agent 的多人式输出、Robot/Monitor 面板和跨 Agent Artifact 共享规则尚未确定。
- 机器人、地图、Skill Studio 与任务追踪需要独立工作区 Layout，不继续堆叠到对话检查器。
- reasoning 只显示服务商实际返回且配置允许的内容，不生成模型未返回的隐藏思维链。
